## Input and execution contract
Use the exact source hashes in COMPONENT_HANDOFF_V5.json. This is an integration candidate, not a standalone V3 public command. Root must supply its registered, pinned selection adapter. Root alone executes numerical checks, serially, with RUN, background/nice10, one native/numeric thread, owner-approved combined command/worker RSS ≤8GiB, invocation ≤55 seconds. The previous256/512MiB budgets are historical and superseded for the central command.

- Matching: import match_session_v1 and call run_many(parent_root, view_spec, canonical_price_root, fresh_out, requested_coins, input_api=registered_adapter, guard=True). All requested coins are required. It writes each coin chunk and final aggregate under fresh_out/aggregate. Admission, load_view and event indexing occur once at the top level; the input adapter may perform its own internal verification. Counters do not claim to count those internal calls.
- Measurement: import prepare_measurements_session_v1 and call prepare(namespace, input_api=registered_adapter, guard=True). Namespace fields are detector_run, lab_root, matcher, comparison_unavailable_reason, out, matching the baseline preparation CLI. The adapter returns the same admitted report fields required by baseline preparation, including _frozen_root, events, requested, unknown_slots. A namespace without matcher needs an explicit comparison-unavailable reason. Every parent and complete eligible edge retains its original identity/weight. At most 1000 explicit requests enter each in-process worker call; one outer deadline covers the invocation. No persisted compiled cache or measurement reuse is introduced.
- Grading: run_session_v1.grade_and_finish(snapshot, canonical_price_root, guard=False, rss_limit_bytes=8*1024**3) keeps batch and finish in one process. Each imported stage accepts guard=False only when root owns the enclosing55-second deadline and aggregate process-tree resource fences. Imported grading requires an explicit integer RSS budget; omission or values above8GiB fail. Legacy standalone guards retain512MiB and are not the approved root execution path. For standalone phases, run_session_v1.py --phase batch --out SNAPSHOT --lab-root <DATA_ROOT>/lab_days invokes existing batch_grade.run once for all PLAN directions/offers/horizons. --phase finish uses the unchanged baseline finish behavior. The run phase currently retains legacy selection discovery; root must bind V3 admission before using it for the fresh acceptance chain.

The V3 support provider must expose load_view, iter_events, mask_arrays and verify_view. mask_arrays.known includes the actual predecessor plus every day's slot. Absent coverage returns false; any unknown predecessor/day slot makes the whole parent's comparison unavailable. No candidate filtering or weight renormalization occurs. Optional day_summary must bind slots to the mask. The provider owns mask validation, source/absence identity and lifetime verification. View pins and the adapter's admitted pins remain bound through final publication.
