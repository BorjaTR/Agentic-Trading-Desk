## The folder
- `<INSTALL>` = this Alarm folder, installed read only: on the Mac `<RELEASE_ROOT>/Alarm/alarm/current`. Run tools from
  it, never edit inside it. Code and tables live here; data lives outside, at the paths of the settings file.
- Settings: `<INSTALL>/settings/SETTINGS_LOCAL.env` (keys in settings/SETTINGS_EXAMPLE.env). Every tool below takes `--settings`.
- From a Cowork VM shell (the Mac's folders under `$HOME/mnt/`), make your own settings file once and give the queue the Mac's for
  the job (jobs run on the Mac): `sed -e "s#=<DEV>#=$HOME/mnt/dev#" -e "s#=<DATA_ROOT>#=$HOME/mnt/volat_store#"
  -e "s#=<SCRATCH_DISK>#=$HOME/mnt/SCRATCH_DISK#" -e "s#^PYTHON=.*#PYTHON=/usr/bin/python3#"
  -e "s#^RUNNER_RELEASE=.*#RUNNER_RELEASE=<RELEASE_ROOT>/Alarm/alarm/current#" <INSTALL>/settings/SETTINGS_LOCAL.env
  > $HOME/SETTINGS_<SEAT>.env`; then every tool takes `--settings $HOME/SETTINGS_<SEAT>.env`, and the queue also
  `--job-settings <INSTALL>/settings/SETTINGS_LOCAL.env` (the job's data paths, as the Mac sees them). The job's code folder is
  RUNNER_RELEASE of your own settings file: a `--dry` job prints it on its AL line. From the VM, `$PY -B _tools/settings_v1.py
  check $HOME/SETTINGS_<SEAT>.env` exits 3 with RUNNER_RELEASE and FEED_GATE MISSING: that is expected (RUNNER_RELEASE is the Mac's
  path, and no gate file means the feed runs); any other MISSING key is a fault.
- You write only in your run folder `RESEARCH_ROOT/ALARM_DESIGN/runs/<RUN>/` (RUN = `<SEAT>_<YYYYMMDD>`, SEAT a capital letter then capitals and digits, at most 12, no underscore: seat SCOUT_R12 writes RUN SCOUTR12_20261103, because every kit tool splits RUN at its one underscore; start it with
  `$PY -B Agentic/tree/ALARM_DESIGN/KIT_V5/tools/start_run_v1.py S <RUN>` (`--dry` first): it copies KIT_V5/runs/TEMPLATE_V4 into a new folder you can write (folders 0755, files 0644, bytes checked), refuses a folder that exists and never writes in the install; a bare `cp -R` keeps the install's read-only modes. Its README_RUN.md names the tools, what a
  run holds and each register's columns; registers are append-only, written with
  `Agentic/tree/ALARM_DESIGN/runs/CLAUDE1_20261028/tools/reg_append_v1.py`), plus your claim and your board line.
- `cards/<tool>.md`: what a tool does, when to use it, the exact command, what it gives, its refusals. Beside it `<tool>.TOOL.json`
  (every command, argument and exit) and `dictionaries/<tool>_COLUMNS.tsv` (every output column: meaning, unit, when known).
- `playbook/PLAYBOOK.md`: how ideas became FOUND alarms, the recipes, what fails; `playbook/FOUND.tsv`: every found or passing alarm.
- RESEARCH_ROOT/ALARM_DESIGN/REGISTRY/: every decided alarm (ALARM_REGISTRY_V1.tsv), SCOREBOARD.md (which families pass), and
  INPUTS_READ_V1.md (which metric codes the alarms read, and the OK codes no alarm reads yet, per family: read your family's section).
- `archive/` folders hold past editions: read only, never run; to rerun one, use the old release install.
