## Inside every part
```
<part>/
  README.md  CHANGELOG.md  RUN_PROOF.md     what it does and its tools; every release; the tests run and what they printed
  MANIFEST.tsv  SOURCES.tsv                 what is copied from the dev tree (written by hand) and each copy's sha16 (written by the sync)
  MACHINE_PATHS.tsv                         every machine path still in the copied files: argument, built in, or text only
  <tool>/                                   one folder per released tool: README (a byte copy), SCOPE, ARCHITECTURE, CHANGELOG
  tree/                                     byte copies of every file the tools run, in the dev tree's layout (paths work unchanged)
  proof_harness/                            (some parts) a small runner written here for a test that needs one; its RUN_PROOF says why
```
A document the dev tree does not have says on its first line that SCOUT (or SCOUT's helper) wrote it for the repo, from which files.

## Shared folders
- [settings](settings): where the data lives on each machine (`SETTINGS_EXAMPLE.env`, `SETTINGS_LOCAL.env`; FORBID names the dev
  tree, so every test proves it does not read it) and the Python packages (`PYTHON_PACKAGES.txt`; pytest for 01's tests).
- `_tools/`: `settings_v1.py` (reads a settings file), `sync_from_dev_v1.py` (copies a part's MANIFEST rows from the dev tree; `--check`),
  `run_isolated_v1.py` (runs one script and fails when a module came from outside this folder or a forbidden file was opened),
  `run_all_tests_v4.py` with `TESTS.tsv` (every test of every part, below; `--workers N` runs N at once, the lines in TESTS.tsv order;
  `--cache-out F` writes a test cache; `--cache-in F` reports a test SAME without running it when its row, the harness, the settings
  and every file it read are unchanged and its PASS is under `--cache-max-days` (7) days old; a FAIL, a KNOWN or a test that starts
  a program the hook cannot watch is never cached; `run_all_tests_v2.py`, no cache, and `run_all_tests_v1.py`, one at a time, are
  its past editions).
- `_vendor/`: LAB1's lab3 reader and writer at the sha16s the releases pin (`LAB3_code`), and the home kit's start-up hook
  (`home_kit/isolation/sitecustomize.py`, hook V1.2 of HOME_KIT_V1_3_3), which watches every Python process of a test, workers
  included, and with the cache on logs every file a test opens.

## Test everything (no data needed: the tests plant their own)
```
python3 -B _tools/run_all_tests_v4.py settings/SETTINGS_<MACHINE>.env --workers 3            # every test in TESTS.tsv, 3 at a time, from this folder
python3 -B _tools/run_all_tests_v4.py settings/SETTINGS_<MACHINE>.env --workers 3 --copy     # the same from a fresh copy elsewhere, this folder forbidden
python3 -B _tools/run_all_tests_v4.py settings/SETTINGS_<MACHINE>.env --workers 3 --cache-in OLD.tsv --cache-out NEW.tsv   # only what changed runs
```
A test passes when it exits 0, prints ISOLATION OK, and no process opened a file under FORBID. Each test gets its own new temporary
folder, removed after it: nothing is written into this folder. 09's tests copy two small library tables of the team's data from
RESEARCH_ROOT (settings). Results: each part's RUN_PROOF.md.

## A new machine
```
git clone <repo> && cd Trading/Alarm
cp settings/SETTINGS_EXAMPLE.env settings/SETTINGS_<MACHINE>.env      # set this machine's data paths and FORBID
bash _tools/setup_python_v1.sh --check                                  # not OK: --install <folder> (settings/README.md, "Setup: Python")
python3 -B _tools/settings_v1.py check settings/SETTINGS_<MACHINE>.env
python3 -B _tools/run_all_tests_v4.py settings/SETTINGS_<MACHINE>.env --workers 3
```
A real run reads the data named in the settings file. Each part's MACHINE_PATHS_KNOWN.tsv lists, with the reason, the kept files that still name a Mac folder; no current tool opens
those paths (_tools/machine_paths_v2.py prints them as KNOWN).

## Install (volat_release)
The Alarm folder is installed as one package, read-only: `<RELEASE_ROOT>/Alarm/alarm/<RELEASE>/` with a `current` pointer
(`<RELEASE_ROOT>/Alarm/alarm/current`). Jobs run only from the install, never from this GitHub folder or the dev tree. Update = install
the new release folder and flip `current`; rollback = flip it back. Nothing is written inside an install. This GitHub folder is the
copy of the current release (git keeps the history).

## Rules
- Released editions only (the kit in Agentic: in use, marked so). A tool is changed in the team's dev tree (new edition, a release),
  then copied here by the sync; it is never edited here.
- Only data lives outside this folder: lab days, the research data, scratch, the job runner. The settings file says where.
- Nothing from May 2026 onward is read by any tool or test here (the team's sealed months).
