# menu_gate_v1: tool card

The SEAL check of the metric menu (AGENTS.md step 5b): a definition, or a TRUE label, that reads a code whose row in `Agentic/tree/ALARM_DESIGN/KIT_V5/METRIC_MENU_V2.tsv` (97a967bd24b34757) is pickable NO is refused, unless the sealed card names the exception and the VARIANTS row records it. Released in ALARM_V1_21_16 (ALARM_V1_21_15 held, never current: GPT V12115-TOOL HOLD fixed; desk trial 4: DESKA04 sealed E1.S04 CAUTION and E1.S09 UNPROVEN and nothing refused them); TEST, NOT REVIEWED.
Code: [menu_gate_v1.py](../Agentic/tree/ALARM_DESIGN/KIT_V5/tools/menu_gate_v1.py). It runs inside [queue_job_v16](queue_job_v16.md) (every kind but COUNT) and prints on the decision through [decide_v6](decide_v6.md).
```
python3 -B <INSTALL>/Agentic/tree/ALARM_DESIGN/KIT_V5/tools/menu_gate_v1.py check <run>/ideas/<IDEA>/defs/<V>.json <run>/ideas/<IDEA>/CARD_<IDEA>.md [--claim <run>/ideas/<IDEA>/TRUE_<V>_<LABEL>.json] [--reason '<the VARIANTS reason>']
```
- A named exception is one card line `MENU EXCEPTION <code>: <why this code is needed>` (at least 12 characters, one line per code) and the words `MENU EXCEPTION <code>` in the reason column of the variant's VARIANTS row. Run `check` at SEAL before the VARIANTS row: it prints the reason words the row needs (`VARIANTS reason must name: ...`); with `--reason` it checks them.
- What is read: the TRUE gate's own reader (true_gate_v1 collect_reads: every code under inputs, conditions, fire, base and mirror; an unknown op is refused) and, for a claim, its label, mirror (code, code_by_side, thr_code) and activity code. The reader is this package's 03_Grading/tree/tools/true_gate/true_gate_v1.py, its bytes pinned (9cef10e960700d6b) and checked before use; only its four reader definitions are run from its source. The menu is pinned too. No environment variable can point the gate at another reader, menu or package.
- Prints `MENU GATE <name>: OK, <n> codes read: <code> <menu_status> pickable <YES|NO> (definition|label)`, one `MENU EXCEPTION <code> (<status>): <reason>` per exception, `MENU NOTE <code>: NOT ON MENU` for a code with no menu row (not refused: the detector's own trap table decides what it can read).
- Refusals (exit 2, `REFUSED <CODE>: <why>`): MENU_NOT_PICKABLE, MENU_EXCEPTION_NOT_RECORDED, BAD_EXCEPTION (no reason, a code twice), UNREADABLE_DEF (not a JSON object, a code that is not a name, an op the reader cannot read), UNREADABLE_CLAIM (not a JSON object; label, mirror, code_by_side or activity of the wrong shape), BAD_REASON, NO_CARD, MENU_CHANGED (the menu is not the pinned bytes), BAD_MENU, NO_MENU, READER_CHANGED, NO_READER. Every malformed shape is one of these, never a traceback.
- What it never does: change what any alarm fires on. The detector, its trap table, the job templates and the pass rules are untouched; it only refuses a seal and prints.
